> **版本：** 1.0.0  
> **更新日期：** 2026-07-20  
> **产品类型：** 认真婚恋小程序 / 移动端应用  
> **设计形态：** product（设计服务产品，而非设计即产品）

---

## 一、产品本质

"宣誓爱"是一款面向认真婚恋人群的中文移动应用。它不是追求快速滑动和即时刺激的陌生人社交产品，而是通过**实名认证、学历/单身等资料认证、双向喜欢、申请认识、专业红娘和线下活动**，帮助用户在可信、安全、具有承诺感的环境里建立长期关系。

### 核心定位

- **不是：** 泛娱乐社交、快速约会、颜值至上的滑动匹配
- **而是：** 真实资料可验证、关系目标明确、双向尊重边界的严肃婚恋平台

### 产品使命

让认真对待长期关系的人，能够在一个真实、安全、有温度的环境中，看见彼此、理解期待、建立信任。

## 二、目标用户

### 核心用户画像

- **年龄：** 24—38 岁
- **城市：** 一二线城市及省会城市
- **婚恋状态：** 单身，对长期关系有明确期待
- **职业特征：** 有稳定工作或事业规划，注重生活品质
- **心理特征：** 
  - 不满足于娱乐化交友的浅层互动
  - 重视真实资料与可信度
  - 希望在了解对方前先确认彼此的关系目标
  - 愿意为认真的关系投入时间与精力

### 使用场景

- **高频场景：** 通勤、午休、晚间碎片时间（15—30 分钟）
- **心理状态：** 
  - 浏览推荐时：快速判断是否值得深入了解
  - 查看详情时：仔细确认资料真实性与关系期待
  - 申请认识时：谨慎且认真，不随意发送

### 用户需求优先级

| 优先级 | 需求 | 产品对应功能 |
|--------|------|--------------|
| **P0** | 快速判断对方是否可信 | 四类认证（实名/学历/头像/单身） |
| **P0** | 了解对方真实生活与性格 | 自我介绍、MBTI、兴趣标签、语音介绍 |
| **P0** | 确认关系期待是否一致 | 择偶要求、关系期待问答 |
| **P1** | 避免骚扰与虚假信息 | 申请制聊天、举报、安全中心 |
| **P1** | 扩大认识范围但不降低质量 | 筛选、同城、红娘推荐 |
| **P2** | 参与真实线下活动 | 线下活动报名与签到 |

## 三、核心价值主张

### 对用户的承诺

1. **真实可验证：** 四类认证体系，降低虚假资料风险
2. **关系目标明确：** 择偶要求与关系期待前置，避免浪费时间
3. **双向尊重边界：** 申请制聊天，拒绝不扣除次数，对方同意后才开启对话
4. **专业辅助服务：** 红娘牵线、AI 合拍度分析、情感实验室
5. **安全与透明：** 安全提示、举报机制、会员权益透明展示

### 产品差异化

| 维度 | 宣誓爱 | 泛娱乐社交 |
|------|--------|------------|
| **匹配方式** | 申请认识 + 红娘推荐 | 双向滑动匹配 |
| **资料真实性** | 四类认证 + 人工审核 | 自由填写 |
| **聊天门槛** | 双方同意后开启 | 匹配即可聊 |
| **付费逻辑** | 透明权益 + 高价值服务 | 频繁打断 + 模糊权益 |
| **社区氛围** | 真实生活分享 + 话题讨论 | 娱乐化内容 |

## 四、产品架构

### 全局导航（5 个一级 Tab）

```
首页 → 推荐 / 广场
社区 → 喜欢 / 同城 / 发现
牵线 → 服务红娘 / 热心红娘 / AI 红娘
消息 → 申请消息 / 纸飞机 / 聊天记录
我的 → 资料管理 / 认证 / 任务 / 会员
```

### 核心流程

#### 匹配流程
```
查看推荐 → 浏览资料 → 喜欢/申请认识 → 对方同意 → 开启聊天
```

#### 认证流程
```
登录 → 安全承诺签署 → 身份选择 → 基础资料填写 → 四类认证
```

#### 会员转化流程
```
免费浏览（3次/日）→ 次数用完 → 权益说明 → 会员套餐 → 支付
```

## 五、商业模式

### 收入来源（按战略优先级）

| 层级 | 变现方式 | 定价策略 | 用户心理 |
|------|----------|----------|----------|
| **免费层** | 引流 + 留存 | 每日 3 次申请、基础推荐、签到积分 | 体验核心功能，建立信任 |
| **会员层** | 订阅制 | 月/季/年套餐 | 高频使用，愿意长期投入 |
| **增值层** | 单次付费 | 爆灯(5元)、置顶(19-199元)、小纸条 | 偶尔需要特殊曝光 |
| **服务层** | 高客单价 | 红娘 1v1 牵线、私人定制 | 对匹配质量要求极高 |
| **活动层** | O2O | 线下活动报名费 | 希望真实见面 |

### 会员权益清单

| 权益 | 普通用户 | 会员用户 |
|------|----------|----------|
| 申请次数 | 每日 3 次 | 无限 |
| 查看访客 | 仅显示数量 | 查看详细列表 |
| 无痕浏览 | ❌ | ✅ |
| 高级筛选 | 城市/年龄/学历 | +收入/MBTI/兴趣 |
| 优先曝光 | ❌ | ✅ |
| VIP 标识 | ❌ | ✅ |

## 六、品牌调性

### 视觉风格

**轻氧极简温柔风** — 暖色调、低饱和、大圆角、柔和阴影

- **不是：** 婚庆俗艳红金、高饱和冷色、生硬撞色
- **而是：** 冷瓷白、青瓷绿、深冷灰、充足留白

### 文案语气

- **克制而真诚：** 不夸大承诺，不制造焦虑
- **温柔而坚定：** 强调真实、安全、尊重边界
- **专业而人性：** 提供指导，但不替用户做决定

### 典型文案示例

| 场景 | ❌ 错误示例 | ✅ 正确示例 |
|------|-------------|-------------|
| 匹配成功 | "恭喜！你们超级配！" | "双方已同意认识。接下来，慢慢了解彼此。" |
| 会员引导 | "今日次数用完！立即开通会员！" | "今日免费次数已用完。会员可无限申请认识。" |
| 安全提示 | "小心骗子！" | "认证只能降低风险，不能替代个人判断。首次见面请选择公共场所。" |

## 七、产品禁区

### 设计禁区

- ❌ 不使用高饱和冷色、纯黑纯白
- ❌ 不堆叠过多标签遮挡人物照片
- ❌ 不把付费入口做成首屏唯一焦点
- ❌ 不使用娱乐化、低俗化装饰元素

### 功能禁区

- ❌ 不允许未认证用户发送私信
- ❌ 不允许用户群发消息骚扰
- ❌ 不在用户不知情的情况下收集隐私数据
- ❌ 不隐瞒会员权益或模糊定价

### 内容禁区

- ❌ 不允许虚假资料、冒用他人照片
- ❌ 不允许色情、暴力、诱导转账内容
- ❌ 不允许线下私约、绕过平台交易

## 十一、技术约束

### 前端技术栈

- **框架：** UniApp X（编译到微信小程序 / iOS / Android）
- **开发模式：** 先用浏览器开发 H5 原型，再迁移到 UniApp
- **设计规范：** 遵循 `DESIGN.md` 固化的设计 Token

### 后端技术栈

- **云服务：** UniCloud（DCloud 官方）
- **数据库：** MongoDB / MySQL（待确认）
- **存储：** 阿里云 OSS / 腾讯云 COS
- **支付：** 微信支付

### 安全与合规

- ❗ 所有用户数据必须加密存储
- ❗ 支付流程必须走官方支付接口
- ❗ 用户隐私数据不得泄露或售卖
- ❗ 用户可随时导出或删除个人数据
