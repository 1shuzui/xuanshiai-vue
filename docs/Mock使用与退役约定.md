# Mock 使用与退役约定

## 1. Mock 的定位

Mock 用于前后端并行开发、页面状态覆盖和接口契约讨论，不是生产数据源，也不是可以随意删除的临时文件。

当前 `api/config.uts` 中 `USE_MOCK = true`，说明工程仍处于 Mock 驱动阶段。

## 2. 退役前提

某个模块只有同时满足以下条件才可切换真实接口：后端接口或云函数已可访问；参数、返回字段、错误码和鉴权已确认；加载、空态、失败、重试和权限状态均已验证；H5 与微信小程序关键流程回归通过；产品负责人确认流程符合申请认识、认证和付费透明规则。

## 3. 退役方式

1. 保持页面只调用 `@/api`。
2. 为目标模块接入真实请求并保留可回退开关。
3. 对比 Mock 与真实响应，修正契约差异。
4. 稳定后清理无价值样例，保留测试夹具和关键状态数据。
5. 更新 `PROJECT_STATUS.md`、本文件与接口文档。

## 4. 禁止事项

- 不直接删除整个 `mock/` 目录。
- 不让页面混用真实接口和直接 Mock 导入。
- 不把 `USE_MOCK = false` 当作上线完成证明。
- 不在真实接口失败时静默伪造成成功数据。
- 不把身份证明、会员状态或认识申请结果写成不透明的前端假状态。

## 5. 验收记录模板

```text
模块：
真实接口/云函数：
已验证状态：加载 / 空态 / 成功 / 失败 / 无权限
H5：
微信小程序：
回退方式：
文档更新：
```
