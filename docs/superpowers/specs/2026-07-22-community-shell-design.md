# 社区／动态高保真 Demo 完善设计规格

- 日期：2026 年 7 月 22 日
- 范围：`design-demos/community-shell/index.html`
- 目标：在单个手机壳高保真 Demo 内，将“社区／动态”从静态信息流补齐为可点击、可回退、可展示关键安全规则与异常状态的完整体验闭环。
- 不在范围：生产 UniApp 页面、消息页、首页、牵线、我的、受保护配置，以及任何订阅购买主路径。

## 1. 设计原则

1. **认真婚恋，而非泛娱乐社交。** 内容、活动与纸飞机均以认识、价值观、线下安全和诚实表达为中心；不使用颜值排名、滑卡匹配、焦虑型文案或关系结果承诺。
2. **认证门槛真实可见。** 可发动态、参与话题、发送纸飞机、申请认识均要求“双重认证”：实名认证通过 + 学历人工审核通过。Demo 要分别展示实名未完成、学历审核中、学历未通过和双重认证完成等状态。
3. **认识申请先于聊天。** 申请认识页要明确说明：双方同意前不能聊天或交换联系方式；仅在“对方同意”结果中出现“前往消息页”的演示入口。
4. **细节状态等同于页面内容。** 每条关键路径至少有默认、有数据、空态、加载／提交中、失败／重试、成功／回流与重复操作保护中的适用状态。
5. **保持同一视觉系统。** 复用现有米白、深青、青绿色、细描边、衬线标题、圆角卡片和手机框结构；新增页面以应用内推入层或全屏层呈现，避免割裂为多套网站。

## 2. 信息架构与页面层

所有页面在同一 `390 × 844` 手机框内切换；详情页使用顶部返回，操作页采用底部抽屉或全屏表单。

```text
发现流
├─ 全部话题 → 话题聚合页 → 话题详情（热门 / 最新） → 参与话题 → 发布页 → 回到话题流
├─ 线下活动 → 活动列表 → 活动详情 → 报名确认 → 报名结果 → 我的活动（状态筛选）
├─ 纸飞机 → 玩法与额度 → 内容编辑 → 发送确认 / 发送结果
├─ 帖子卡 → 帖子详情 → 评论 / 回复 / 点赞
├─ 作者操作 → 申请认识 → 认证拦截 / 附言 / 配额 / 状态结果
├─ 更多 → 举报 → 原因 / 说明 / 提交状态 → 成功说明
└─ 通知 → 互动通知（有数据 / 空态）

关注 / 同城 / 发现
├─ 关注：全部 / 关注 / 我的；无关注内容时可回流“逛逛发现”
├─ 同城：全部 / 热门 / 最新；明确“同城”地理标签
└─ 发现：全部 / MBTI / 校友；顶部展示话题、活动、纸飞机入口
```

## 3. 核心页面与交互细节

### 3.1 社区主壳与动态流

- 顶部：动态流分段（关注 / 同城 / 发现）、右侧通知、当前分区二级筛选；切换时保留各分区的内容和空态。
- 每张动态卡：头像、姓名、年龄／城市、认证标签、发布时间、主题或话题标签、正文、媒体占位、收藏／喜欢／评论／更多操作、互动数字。
- 同城卡增加“同城 · xx 区”标签；发现卡增加 MBTI 或校友标签；认证标识不夸大，不把实名认证误写成双重认证。
- 发现顶部 Banner：`话题`、`线下活动`、`纸飞机` 三个内容明确、可点击的行动卡；补充简短说明和数量／次数信息。
- 增加信息流骨架屏、网络失败卡与“重新加载”；关注为空时给出“逛逛发现”回流按钮。

### 3.2 话题闭环

- 全部话题页：近期热门和更多话题两组，展示话题名称、简介、参与人数、浏览量与正在讨论的方向。
- 话题详情：主题背景、话题名、简介、参与人数、浏览量、热门／最新切换、精选动态流和无内容空态。
- “参与话题”自动带入当前话题；未完成双重认证时弹出认证缺口说明，并提供“查看认证进度”而不允许绕过。
- 发布成功后在话题流顶端插入新卡，并有“已发布到 #话题#”反馈。

### 3.3 帖子详情与评论

- 点击整张卡或评论按钮进入帖子详情，原帖保留完整内容、媒体、认证信息、互动统计与更多操作。
- 评论区区分“评论”和“回复某人”，展示评论者、时间与折叠回复；无评论时展示礼貌空态。
- 输入框包含字数提示、发送禁用态；发送时显示提交中并锁定重复点击；失败时保留输入内容与“重试”。
- 点赞是轻意向互动，只改变当前卡或详情中的数量与状态；收藏仅作为“仅自己可见”的提示，不向作者暴露。

### 3.4 线下活动

- 活动列表：活动海报、主题、时间、地点、人数、报名状态、主办方和“活动说明”摘要。
- 活动详情：完整时间／地点／交通提示、报名人数／名额、主办方、参与前注意事项、信息保护与线下安全提示。
- 报名：确认个人资料将用于活动组织联络；状态依次为确认、提交中、报名成功或网络失败重试。
- 我的活动：`全部 / 报名成功 / 待审核 / 被拒 / 已签到` 筛选，包含空态和返回发现页。

### 3.5 纸飞机

- 首屏说明收件范围、匿名边界、今日剩余次数和安全提醒；不暗示立即配对或公开联系方式。
- 编辑页包含话题／心声、收件范围、文本字数和发送前确认；未认证必须拦截。
- 剩余次数用完时，清楚展示“积分兑换 1 次”“查看会员权益”两个入口；会员入口只做权益说明，不允许绕开对方同意或认证。
- 发送拥有确认、提交中、成功、网络失败及重试；成功页明确“对方可选择回应，双方同意前不会开放聊天”。

### 3.6 申请认识状态机

- 前置页显示双方基本信息、剩余配额（每日 3 次）、附言输入、缘由／共同话题和安全提示。
- 四种认证拦截：实名未完成、学历审核中、学历未通过、双重认证已完成；仅最后一种进入提交。
- 状态：可申请 → 提交中 → 等待对方回应 → 对方同意／对方拒绝；申请中禁用重复提交。
- 额度用尽时明确显示“积分兑换一次”和“查看会员权益”，不隐藏限制、不承诺购买后直接聊天。
- 对方同意的成功状态显示“已解锁聊天”，仅提供“前往消息页（演示）”提示；拒绝状态提供平静回流到社区的按钮。

### 3.7 发布动态

- 操作入口：图文、视频、表情、话题；支持从话题页自动带入话题。
- 表单包括正文、标签、位置可选项、媒体计数、内容规范和“发布后将接受内容审核”的提示。
- 正文为空且未添加媒体时禁用发布；内容过短、超字数、媒体未就绪、网络异常各有明确提示。
- 提交中锁定按钮；发布失败保留草稿与重试；成功后回流至来源页（普通发布回发现，话题发布回话题详情）。

### 3.8 举报与安全屏蔽

- 更多菜单只保留安全行动：举报、拉黑／不看该用户、取消；删除“不感兴趣”“减少此类内容”等算法负反馈文案与逻辑。
- 举报流程：原因选择 → 补充说明（可选）→ 提交中 → 成功说明。成功文案解释后续由平台按规则处理，不承诺即时处置结果。
- 拉黑／不看该用户是个人安全屏蔽，明确会隐藏该用户动态，且可在安全中心管理；不将其表述为内容推荐算法训练。

### 3.9 通知与辅助状态

- 通知页展示点赞、评论、话题互动与活动报名的示例数据；空态展示“暂时没有新通知”。
- 各主入口提供回退路径，避免出现无法退出的浮层。
- 所有提交型操作包含防连点、按钮文案变化和可感知的成功／失败反馈。

## 4. 数据与状态模型（Demo 内存态）

```text
view: feed | topicList | topicDetail | postDetail | activityList | activityDetail |
      myActivities | paperPlane | notifications

overlay: none | publish | certificationGate | application | applicationResult |
         report | actionMenu | commentComposer | eventSignup | paperPlaneComposer

certification:
  realName: passed | missing
  education: passed | reviewing | rejected

quotas:
  applyDaily: { total: 3, used: number, pointsAvailable: boolean }
  paperPlaneDaily: { total: number, used: number, pointsAvailable: boolean }

network: ready | loading | error
submission: idle | pending | success | error
```

初始数据至少覆盖：已认证作者、仅实名作者、学历审核中用户、已申请对象、不同活动报名状态、空评论帖子、热门话题与网络失败演示入口。

## 5. 视觉与文案细节

- 标题层级采用衬线字体，信息／操作采用无衬线字体；二级信息弱化为灰绿色，不增加新的强艳色。
- 操作按钮有清晰主次：主按钮深青底浅色字，次按钮描边，危险操作只使用克制的深红文字与二次确认。
- 认证、次数、状态均以小型标签／提示条承载，不用弹窗堆叠全部规则。
- 容器保持 12–18px 内边距、8–14px 间距、圆角卡片和细描边；底部固定操作区为滚动内容预留安全高度。
- 文案避免“脱单”“命中注定”“最后机会”“立即匹配”等压力和结果承诺；用“了解”“回应”“共同话题”“安全参与”等表达。

## 6. 验收清单

1. 发现 Banner、话题、活动、纸飞机均可进入并返回相应页面。
2. 帖子详情可评论／回复，展示空态、提交中、失败重试和成功后的列表更新。
3. 申请认识准确执行双重认证、每日次数、附言、防重复提交和双方同意前禁止聊天的规则。
4. 发布与话题参与准确执行双重认证、内容校验、审核提示、失败重试和回流。
5. 活动报名和纸飞机都有额度／状态／失败重试／成功后的说明。
6. 更多菜单及逻辑中不再出现“不感兴趣”或“减少此类内容”。
7. 至少提供信息流加载、空态和网络失败状态入口；各浮层可关闭或返回。
8. 不修改生产页面、`manifest.json`、`pages.json`、`uniCloud-aliyun/`、依赖或项目运行配置。
