# 图片、上传与包体注意事项

## 1. 当前资源

正式源码中的肖像资源位于 `static/portraits/`。`manifest.json` 还引用了 `static/logo.png`，但当前仓库没有正式品牌图标；这是发布前待补项，不应使用人物照片或临时占位图冒充品牌图标。

## 2. 静态图片

- 入库前压缩，列表图与详情图使用合适尺寸。
- 优先 WebP；需要平台兼容时提供 JPEG/PNG 降级。
- 业务资源放入 `static/` 的明确子目录，不散落在页面目录。
- 大图、视频和大量相册资源优先走经过授权的远端存储，不堆入主包。
- `../../design-demos/final/assets/` 是外部参考素材，不作为生产资源源目录。

## 3. 用户上传

上传头像、相册、动态或认证材料时必须处理选择、压缩、上传中、成功、失败、取消和拒绝授权；张数、文件类型、单张大小和总大小限制；敏感认证材料的最小化收集、用途说明和删除机制。

头像/相册与实名材料要分开存储和展示，不泄露认证原件。

## 4. 小程序包体

- 页面与资源增多时评估分包，但修改 `pages.json` 前必须获得确认。
- 不安装依赖 DOM 的图片库或 Web 专用上传库。
- 新依赖先说明用途、跨端兼容性和体积影响。
- `unpackage/` 是构建产物，不作为资源源目录。

## 5. 发布前

- [ ] 正式品牌图标已补齐并经过设计确认。
- [ ] 主包与分包体积符合目标平台限制。
- [ ] 上传权限说明与真实功能一致。
- [ ] 隐私政策覆盖图片、相机、相册与认证材料。
- [ ] 微信开发者工具真机预览通过。
